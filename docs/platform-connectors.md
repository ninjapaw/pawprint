# Platform connector management

The local PawPrint Portal inventories platform connections before offering any
change. Open `http://127.0.0.1:4173/setup/platform/` after `npm run portal`.

## States

| State          | Meaning                                                                            |
| -------------- | ---------------------------------------------------------------------------------- |
| `managed`      | A matching resource exists and carries the Pawprint Bicep management tag.          |
| `pre-existing` | A healthy matching resource exists but is not declared as Pawprint-managed IaC.    |
| `needs-action` | The Azure shell exists but provider authorization is incomplete or broken.         |
| `eligible`     | No matching resource was found; onboarding can be considered.                      |
| `unavailable`  | The current identity cannot inspect the provider, so absence must not be inferred. |

The inventory is read-only. It scans Azure Resource Manager, Microsoft Graph,
GitHub, and secret names. Secret values are never requested or returned.
GitHub Enterprise discovery requires the GitHub CLI identity to have
`read:enterprise`; without it, the portal reports unavailable rather than
eligible.

## Permission model

Read-only access is useful and supported. The portal reports the signed-in
operator's effective Azure and Entra roles before enabling management controls.

- Azure inventory: `Security Reader` at the narrowest useful scope.
- Defender connector management: `Security Admin` at the relevant scope.
- Entra inventory: `Directory Readers` or `Global Reader`.
- Gallery app management: `Cloud Application Administrator`.
- User/group assignment management: add `Groups Administrator` when group
  administration is also required.

Routine platform management should not depend on `Owner` or `Global
Administrator`. The portal flags Owner assignments and recommends narrower
roles. Break-glass roles should be eligible, time-bound, audited, and separate
from normal operations.

Enterprise application access is assigned to Entra users or security groups
through app roles. Prefer groups for ongoing membership. This feature does not
create directory owners, GitHub enterprise owners, or Azure DevOps organization
owners.

## Automation boundaries

The validated catalog at `config/platform-connectors.catalog.json` identifies
each connector as:

- `bicep`: Azure Resource Manager can own the resource declaratively.
- `hybrid`: Bicep or Graph owns Azure/Entra state, followed by provider-side
  consent or authorization.
- `guided`: purchase, billing, account creation, recovery-code capture, or
  another human control cannot safely be replaced by unattended automation.

Defender DevOps connector shells for GitHub, Azure DevOps, and GitLab use
`modules/defender-devops-connector/main.bicep`. The current development desired
state is declared in `infra/platform-connectors/main.dev.bicepparam` and
deployed through `infra/platform-connectors/main.bicep`.

`Preview declared IaC` always runs before operators choose `Apply declared
IaC`. Apply affects only resources explicitly present in the reviewed parameter
file. Pawprint deliberately does not deploy every merely eligible item: a scan
finding is not consent, and several connectors can add cost or standing access.

## Provider walkthroughs

- Defender GitHub: Bicep connector shell, Defender authorization, GitHub App
  organization-owner approval, authorization health rescan.
- Defender Azure DevOps: Bicep connector shell, organization authorization,
  project selection, health rescan.
- Defender GitLab: Bicep connector shell, group-owner authorization, credential
  storage where issued, health rescan.
- AWS/GCP: Azure-side connector declaration plus the provider trust stack or
  workload identity steps generated by Defender for Cloud.
- GitHub Enterprise: account/trial/upgrade remains a GitHub owner and billing
  action. Choose personal accounts versus Enterprise Managed Users first.
- Azure DevOps organization: creation and region/owner selection remain an
  account-level guided action, followed by Entra tenant connection.
- Entra gallery: instantiate or adopt the gallery enterprise app, assign Entra
  groups, configure and test provider SSO, and capture recovery codes before
  enforcement.

SCIM design is chosen before activation. Enterprise-level SCIM requires GitHub
Enterprise Managed Users; otherwise provisioning is organization-scoped.

## Lifecycle controls

Every catalog entry declares applicable actions from `scan`, `onboard`,
`repair`, `rotate`, `access`, `disable`, and `remove`. Guided actions open the
authoritative provider flow with a checklist. Bicep actions use fixed local IaC
paths and accept no browser-supplied resource IDs or templates.

Destructive disable/remove actions are not included in bulk onboarding. Remove
a connector from declared desired state, preview the change, complete any
provider-side deauthorization, then apply the reviewed change. Credential
rotation stores new values directly in the target secret store and retains only
non-secret identity/expiry metadata for status reporting.
